# AudioCpp.NET 0.1.0

.NET 10 bindings for [audio.cpp](https://github.com/0xShug0/audio.cpp), built on a small
versioned C ABI shim over `engine_runtime`.

## Packages

| Package | Contents |
| --- | --- |
| `AudioCpp.NET` | Managed API, with the Interop assembly folded in — no separate dependency to restore |
| `AudioCpp.NET.Runtime` | Native CPU assets for `win-x64` and `linux-x64` |
| `AudioCpp.NET.Runtime.Cuda` | Native CUDA assets for `win-x64` and `linux-x64` |

Reference **exactly one** runtime package. Both ship a shim with the same file name, so
referencing both fails the build with an explicit error instead of silently picking one.

## Pinned upstream

The engine source is pinned to a reviewed commit; this repository never builds an
unreviewed moving `main`.

- Repository: `https://github.com/0xShug0/audio.cpp`
- Commit: `78d47706c30ef215ba9ad3559baff309efeb5260`
- Lock file: [`eng/upstream.lock.json`](../../eng/upstream.lock.json)

## Release assets

`audiocpp-native-{win-x64,linux-x64}-{cpu,cuda}.zip` carry the native shims that
`release.yml` assembles into the runtime packages. Attach them to this release before
pushing a version tag, otherwise the workflow packs the managed package only and skips
the runtime packages with a warning.
